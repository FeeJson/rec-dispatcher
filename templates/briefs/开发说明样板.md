## 怎么做

1. 读这一页的线上代码，列出全部分支：接口回的每种状态、空数据、筛选和分页、无权限、加载中、加载失败、提交中、保存失败、各种弹窗（新增、编辑、详情、确认、日志）、表单校验提示、按钮的各种状态、轻提示。每个会让运营看到不同画面的分支都做成一个演示状态。
2. 先写清单，导出，跑 `check/check_page.js`、`check/contact.js` 看拼图。清单可以用一段 Python 生成，生成脚本不用留。
3. 逐个状态看画面，和真机截图对一下（有截图的话），确认和线上代码跑出来的一样。
4. 找线上问题，见下一节。逐条读代码、看画面判断，不要用脚本机械比对。
5. 每条线上问题写一个「正确样子」状态：名字写成 `正确样子/<短名>`，用 `patch` 在线上源码上打补丁生成，补丁改得越少越好。真的画不出来的，`fixed` 写 `null`，用 `fixNote` 说明。正确样子有现成依据的照依据画，没有依据的照本页已有的样式风格补，并在报告里写明是你定的。

7. 对照老原型截图和对照数据，写 `changes.revised`、`changes.added`。
8. 写报告，发 `worker_done`。

## 什么算线上问题

照小程序已认可的几类，换成后台的样子：

- 报错原文给运营看：网关出错时显示「Failed to execute 'json' on 'Response': Unexpected token '<'…」、断网时显示「Failed to fetch」这类英文。根子多在 `services/request.ts` 直接 `resp.json()`、页面把 `error.message` 原样放出来。接口回的中文 message 是正常提示，不算。
- 出错归错类：接口出错也说「没有符合筛选条件的…」「暂无数据」，像是真的没有。
- 过渡态误导：加载中先显示空表格、「共 0 条」「没有符合条件的…」，像是没内容。
- 出错后没出路：没有重试、按钮消失、点了没反应也没提示。
- 文案像开发用语，或原始值没翻译：英文状态、枚举值（`paid`、`subscription` 这类）、`null`、`undefined` 直接显示。后台列表、日志里的时间到秒照线上，不算问题。
- 布局瑕疵：折行掉字、互相遮挡、表格列挤压、弹窗超出屏幕、按钮被挡住。
- 功能错：筛选、分页不生效或条数不对，状态写死，金额、日期算错，按钮放了不该放的操作。
- 没权限的正确样子：全站统一写「没有这一页的权限，请联系管理员开通」（主控定）。
- 最后一页删空回不去：最后一页只剩一条时删除、停用，或者改了正被筛选的那一项，页面按原页码重取会拿到空页。共用分页条把页码压到最大页（`components/Pager.tsx:36-37`），点那一页又不响应（`:55-57`），运营回不到有数据的页。O03、C02、S01 都算了；有删除、停用、改状态的分页列表逐个走一遍。
- 违反用户定的后台规矩：长表格要冻结左边定位列和右边操作列；页面上不放解释说明的文字；二级弹窗要明显比一级窄、位置更靠下。
- 后台和小程序对不上：后台能配出来的样式小程序没做，后台预览和小程序实际显示不一样，后台保存时转义了的文字原样显示。

不算线上问题：只是和老原型不一样（那是线上改版）、代码写法问题、运营走不到的分支。拿不准的写进报告的「拿不准」，不要硬算。

## config.js 格式

```js
// <页面编号> <页面名>：演示状态和线上问题，外壳 index.html 按这份配置展示
// 状态页和正确样子由 还原工具/admweb/specs/<页面编号>-proto.json 导出到本目录
window.PROTO_PAGES = window.PROTO_PAGES || [];
window.PROTO_PAGES.push({
  id: 'D01',
  side: 'admin',
  name: '订单管理',
  module: '交易结算管理',
  route: 'trade/order',
  desc: '一句话说这一页是干什么的、谁在用。',
  states: [
    { name: '默认', desc: '一句话说这个状态是什么情况、怎么到的。' },
  ],
  issues: [
    { n: 1, title: '加载失败显示报错原文', online: '线上现在是什么样。', fix: '正确样子是什么样。',
      state: '加载失败', marks: [{ sel: '.选择器', cap: '短标签' }],
      fixed: '正确样子/加载失败提示', fixedMarks: [{ sel: '.选择器', cap: '短标签' }] },
  ],
  changes: {
    revised: ['线上改版，一处一行'],
    added: ['线上新增，一项一行'],
  },
});
```

- `side: 'admin'` 一定要写，外壳靠它把页放进管理后台分类。`module` 照上面的表。
- `states[].file`：导出的文件名和状态名不一样时写。
- 状态顺序：正常的在前，变化的（筛选、弹窗）在中间，过渡态和出错在后，专门演示某条问题的放最后。
- `issues[].state` 是这条问题在哪个状态里看得到；`marks` 框线上画面，`fixedMarks` 框正确样子。
- 框的写法：`sel` 选择器（或 `text` 按文字找），`nth` 第几个（从 0 数），`cap` 框旁的短标签（12 个字以内），`fit: 'text'` 只框元素里的文字。框要对准那个元素，不要框整块、整行。外壳里点问题编号会按框的位置对焦放大（至少放大到 0.85 倍）：整行的宽框放大后两头会被裁，文字可能正好落在被裁的那头，所以报错提示、按钮这类要框文字本身。一条问题框了几处、相隔很远时，外壳对焦到第一处，把最要紧的那处放第一个。同一状态里几个框挨得近时，看拼图里标签有没有互相压住。
- 说明文字写白话：界面原文放「」；不写文件路径、类名、代码词（报错英文原文可以照引）；短句，不用比喻，不写「甲方」；不写「待确认」「补充」这类内部字眼。
